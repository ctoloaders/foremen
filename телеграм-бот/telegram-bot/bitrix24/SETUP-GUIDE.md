# Настройка Битрикс24 с нуля — пошагово

Ты только что создал аккаунт. Ниже — куда нажимать на каждом этапе.

Предположим, адрес твоего Битрикс24: `https://XXXX.bitrix24.ru`

---

## Часть 1: Добавить поля в профиль сотрудника

Нам нужно 2 поля: **Telegram ID** (число) и **Роль для бота** (список).

### Шаги:

1. **Нажми на свою аватарку** (фото в правом верхнем углу)
2. В выпадающем меню нажми **своё имя** (откроется твой профиль)
3. В профиле нажми кнопку **"Создать поле"** (или "Create field")

#### Поле 1: Telegram ID

4. Выбери тип: **Число** (Number)
5. Название поля: `Telegram ID`
6. Поставь галку **"Всегда показывать"** (Always show)
7. Нажми **Сохранить**

#### Поле 2: Роль для бота

8. Снова нажми **"Создать поле"**
9. Выбери тип: **Список** (List)
10. Название поля: `Роль для бота`
11. Добавь варианты списка (по одному):
    - `foreman`
    - `pm`
    - `estimator`
    - `sales`
    - `admin`
    - `other`
12. Поставь галку **"Всегда показывать"**
13. Нажми **Сохранить**

#### Заполни свои поля:

14. В своём профиле нажми **Редактировать** (или кликни на поле)
15. Telegram ID: `571744833`
16. Роль для бота: `admin`
17. Сохрани

> **Только администратор Битрикс24 может создавать поля в профиле.** Если ты владелец аккаунта — ты автоматически администратор.

## Часть 2: Создать проект

### Шаги:

1. В левом меню нажми **"Задачи и проекты"** (или просто **"Проекты"**)
2. Перейди на вкладку **"Проекты"** (наверху)
3. Нажми кнопку **"Создать"** → **"Проект"**
4. В открывшемся окне:
   - Название: `Тест-проект`
   - Описание: (можно пропустить)
   - Владелец: ты (по умолчанию)
5. Нажми **"Создать"**

Проект создан. Теперь добавим кастомные поля.

## Часть 3: Добавить кастомные поля в проект

В облачном Битрикс24 **нельзя** напрямую добавить пользовательские поля в карточку проекта через интерфейс (это ограничение облачной версии). Но есть обходной путь — использовать **REST API** (входящий webhook).

### Шаг 3.1: Создать входящий webhook

1. В левом меню внизу найди **"Разработчикам"** (Developer resources)
   - Если не видишь — нажми **"Ещё"** в левом меню → появится "Разработчикам"
   - Или перейди по URL: `https://XXXX.bitrix24.ru/devops/section/standard/`
2. Нажми вкладку **"Готовые сценарии"** (Ready-made scenarios)
3. Нажми **"Другое"** (Other)
4. Нажми **"Входящий вебхук"** (Incoming webhook)
5. Откроется панель с **URL вебхука** — скопируй его (выглядит как `https://XXXX.bitrix24.ru/rest/1/xxxxxxx/`)
6. В разделе **"Настройка прав"** (Permissions) поставь галки:
   - ☑ Рабочие группы (sonet_group) — или "Workgroups"
   - ☑ Пользователи (user)
7. Нажми **Сохранить**

Запиши URL — он понадобится для следующего шага.

### Шаг 3.2: Создать поля проекта через API (curl)

Открой терминал и выполни (подставь свой URL вебхука вместо `WEBHOOK_URL`):

```bash
# Поле: Ссылка на Google Drive
curl "WEBHOOK_URL/sonet_group.feature.access?GROUP_ID=1" 

# Проще: создадим поля через Списки (Lists) внутри проекта — см. Часть 3 альтернатива
```

> **Альтернативный (проще) подход:** Вместо пользовательских полей на группе — используем **Список (Universal List)** внутри проекта для хранения метаданных. Но для MVP ещё проще:

### Шаг 3.2 (простой путь): Хранить URL'ы в описании проекта

Для тестирования **не нужны** кастомные поля на проекте вообще! Схема:

1. Робот Битрикс24 (или ты вручную) дёргает наш webhook
2. Webhook сам создаёт папку + смету и записывает всё в Google Sheets реестр
3. Битрикс24 получает URL'ы в ответе — их можно вписать в **описание проекта** (или просто проигнорировать — реестр уже обновлён)

**Для теста достаточно:** просто вызвать webhook curl'ом с названием проекта. Бот будет читать проекты из Google Sheets, а не из Битрикс24.

## Часть 4: Создать исходящий webhook (Битрикс → наш сервер)

Исходящий webhook — это когда Битрикс24 **сам отправляет** POST-запрос на наш URL при событии.

### Шаги:

1. Перейди: **Разработчикам** (Developer resources)
   - Левое меню → "Ещё" → "Разработчикам"
   - Или URL: `https://XXXX.bitrix24.ru/devops/section/standard/`
2. Вкладка **"Готовые сценарии"** → **"Другое"** → **"Исходящий вебхук"** (Outgoing webhook)
3. Заполни:
   - **Код события**: выбери `ONSONETGROUPADD` (создание группы/проекта)
   - **URL обработчика**: `http://localhost:3000` (для теста; позже заменишь на URL Cloud Function)
   - **Название**: `Sync Project`
4. Нажми **Сохранить**

> **Проблема:** исходящий webhook отправляет данные **в формате Битрикс** (не в нашем JSON). Поэтому для реальной интеграции лучше использовать **бизнес-процесс** (Часть 5). Для быстрого теста — используй curl (Часть 6).

---

## Часть 5: Бизнес-процесс с HTTP-запросом (правильный способ)

Бизнес-процесс позволяет отправить **произвольный JSON** на наш webhook.

### Шаги:

1. Перейди в проект: **Задачи и проекты** → **Проекты** → открой `Тест-проект`
2. Внутри проекта найди раздел **"Списки"** (Lists) в левом меню проекта
   - Если нет — нажми **"Ещё"** или добавь инструмент "Списки" в настройках проекта
3. Создай новый список: **"Метаданные проекта"** (или любое название)
4. В этом списке перейди: **Настройки** (шестерёнка) → **Бизнес-процессы** → **Добавить шаблон**
5. Добавь действие **"Запрос по URL"** (или "Webhook request"):
   - URL: `http://localhost:3000` (для теста)
   - Метод: POST
   - Заголовок: `Content-Type: application/json`
   - Тело:
```json
{
  "secret": "foremen-apps-script-secret-2024",
  "action": "upsert_project",
  "project_name": "Тест-проект",
  "workers": [
    {"worker_name": "Alexander Borohov", "role_in_project": "admin"}
  ]
}
```

> **Честно:** бизнес-процессы для групп/проектов в облачном Битрикс24 ограничены. Самый надёжный путь для теста — **Часть 6** (curl руками).

## Часть 6: Тест без всякой автоматизации (рекомендуется для начала)

Пока не заморачивайся с роботами. Проверим что вся цепочка работает через curl.

### Шаг 6.1: Запусти webhook-сервер

```bash
cd телеграм-бот/telegram-bot
bun run dev:webhook
```

Увидишь: `Webhook dev server running on http://localhost:3000`

### Шаг 6.2: Создай работника (тебя) в реестре

```bash
curl -X POST http://localhost:3000 \
  -H "Content-Type: application/json" \
  -d '{
    "secret": "foremen-apps-script-secret-2024",
    "action": "upsert_worker",
    "bitrix_user_id": "1",
    "worker_name": "Alexander Borohov",
    "role": "admin",
    "telegram_id": 571744833
  }'
```

Ответ: `{"status":"ok","message":"worker upserted"}`

### Шаг 6.3: Создай проект (автоматически создаст папку + смету)

```bash
curl -X POST http://localhost:3000 \
  -H "Content-Type: application/json" \
  -d '{
    "secret": "foremen-apps-script-secret-2024",
    "action": "upsert_project",
    "project_name": "Квартира Иванова",
    "workers": [
      {"worker_name": "Alexander Borohov", "role_in_project": "pm"},
      {"worker_name": "Alexander Borohov", "role_in_project": "foreman"}
    ]
  }'
```

Ответ:
```json
{
  "status": "ok",
  "message": "project created with new resources",
  "google_drive_url": "https://drive.google.com/drive/folders/...",
  "google_sheets_url": "https://docs.google.com/spreadsheets/d/.../edit"
}
```

**URL'ы из ответа** — это то что в будущем робот Битрикс24 автоматически запишет в поля проекта.

### Шаг 6.4: Проверь результат

1. Открой **Реестр проектов**: https://docs.google.com/spreadsheets/d/1YjSN9w_OpCFKNElj0Nrhvva2JgWlMtmSHbiVDFuSKaQ/edit
   - Лист "projects" — должна быть строка "Квартира Иванова" с URL'ами

2. Открой **Реестр работников**: https://docs.google.com/spreadsheets/d/10Y_f33aXzBhCz55y-l-GeX5raYeyTZb9gGiQt6azchs/edit
   - Лист "workers" — Alexander Borohov, admin
   - Лист "project_access" — привязка "Квартира Иванова" → "Alexander Borohov"

3. Открой **Shared Drive**: https://drive.google.com/drive/u/0/folders/0AHkU6n74cG-CUk9PVA
   - Папка "Проекты" → "Квартира Иванова — Чеки" → "Квартира Иванова — Смета"

### Шаг 6.5: Проверь Telegram бота

1. Убедись что бот запущен: `bun run dev` (в другом терминале)
2. Открой бота в Telegram
3. Отправь `/start`
4. Должен показать кнопку "Квартира Иванова"
5. Нажми → отправь фото → введи сумму → описание → магазин
6. Проверь что строка появилась в смете и фото в папке

## Часть 7: Что настроить в Битрикс24 когда всё заработает

Когда ты убедился что curl'ы работают — настрой автоматизацию в Битрикс24:

### Вариант A: Через REST API + Event Handler (рекомендуется)

1. Создай **локальное приложение** в Разработчикам:
   - Тип: "Серверное приложение"
   - URL обработчика: URL твоей Cloud Function `bitrix-webhook`
   - Подпишись на события: `ONSONETGROUPADD`, `ONSONETGROUPUPDATE`, `ONUSERUPDATE`
2. При срабатывании события — Битрикс отправит POST на твой URL с данными
3. Твой webhook обработает и вернёт результат

### Вариант B: Через скрипт на сервере (polling)

Запускать cron-скрипт который раз в минуту проверяет Битрикс24 через REST API:
- `sonet_group.get` — получить список проектов
- `user.get` — получить список сотрудников
- Сравнить с реестрами и обновить

### Вариант C: Руками через интерфейс + webhook

После каждого создания/изменения проекта — менеджер вручную запускает "рабочий процесс" (кнопка в проекте) который дёргает webhook.

## Итого: минимальный сетап для теста

| Что сделать | Где | Время |
|-------------|-----|-------|
| Создать поля в профиле (Telegram ID, Роль) | Профиль → Создать поле | 2 мин |
| Заполнить свои поля | Профиль → Редактировать | 30 сек |
| Создать проект "Тест-проект" | Проекты → Создать | 1 мин |
| Запустить webhook-сервер локально | Терминал: `bun run dev:webhook` | 5 сек |
| Протестировать curl'ами | Терминал | 2 мин |
| Проверить таблицы и бота | Браузер + Telegram | 2 мин |

**Общее время: ~8 минут**

Автоматизация (роботы, бизнес-процессы) — это следующий шаг, после того как убедишься что вся цепочка работает.
