## Концепция: почему Сделки, а не Проекты

В облачном Битрикс24 "Проекты" (рабочие группы) **не поддерживают** кастомные поля через интерфейс. Зато **Сделки в CRM** поддерживают всё что нам нужно:
- Кастомные поля (строка, число, привязка к сотруднику)
- Роботы с действиями (webhook, изменение полей)
- Бизнес-процессы

**Наш подход:** каждый ремонтный проект = **Сделка** в CRM. Это стандартная практика для ремонтных компаний в Битрикс24.

## Часть 1: Добавить поля в профиль сотрудника (2 мин)

### Что делаем: 
Добавляем Telegram ID и роль чтобы webhook мог синхронизировать работников.

### Шаги:

1. **Нажми на свою аватарку** в правом верхнем углу экрана
2. В выпадающем меню **нажми на своё имя** — откроется страница твоего профиля
3. На странице профиля найди кнопку **"Создать поле"** (Create field) — она под основными данными

#### Создай поле "Telegram ID":

4. Нажми **"Создать поле"**
5. В списке типов выбери **"Число"** (Number)
6. В поле "Название" напиши: `Telegram ID`
7. Поставь галку ☑ **"Всегда показывать"** (Always show)
8. Нажми **"Сохранить"**

#### Создай поле "Роль для бота":

9. Нажми **"Создать поле"** ещё раз
10. Выбери тип **"Список"** (List)
11. Название: `Роль для бота`
12. Нажми "Добавить вариант" и добавь по одному:
    - `foreman`
    - `pm`
    - `estimator`
    - `sales`
    - `admin`
    - `other`
13. Поставь галку ☑ **"Всегда показывать"**
14. Нажми **"Сохранить"**

#### Заполни свои данные:

15. Нажми на поле **"Telegram ID"** → введи: `571744833` → нажми Enter или кликни вне поля
16. Нажми на поле **"Роль для бота"** → выбери: `admin`

✅ Готово — теперь у тебя в профиле есть TG ID и роль.

## Часть 2: Настроить CRM — воронка для проектов (5 мин)

## Часть 3: Настроить робота (автоматизация) (5 мин)

### Что делаем:
Когда Сделка создана или изменена — робот дёргает наш webhook. Webhook создаёт папку + смету и возвращает URL'ы. Робот записывает их в поля сделки.

### Шаг 3.1: Открыть настройку роботов

1. В CRM → Сделки → нажми **"Роботы"** (вверху, рядом с "Канбан" и "Список")
   - Или: настройки ⚙️ → **"Роботы и триггеры"**
2. Выбери стадию на которой хочешь запускать робота (например **первая стадия** — "Новая", или "В работе")
3. Нажми **"+"** (добавить) на этой стадии

### Шаг 3.2: Добавить робот "Запрос по URL"

1. В списке роботов найди **"Запрос по URL"** (HTTP Request / Webhook)
   - Может быть в категории "Другое" или "Для разработчиков"
2. Нажми на него
3. Настрой:

**URL обработчика:**
```
http://localhost:3000
```
> (Для теста — localhost. Потом заменишь на URL Cloud Function)

**Метод:** POST

**Тип тела запроса:** JSON

**Тело запроса:**
```json
{
  "secret": "foremen-apps-script-secret-2024",
  "action": "upsert_project",
  "project_name": "{{Название}}",
  "google_drive_url": "{{UF_CRM_GOOGLE_DRIVE_URL}}",
  "google_sheets_url": "{{UF_CRM_GOOGLE_SHEETS_URL}}",
  "workers": [
    {"worker_name": "{{UF_CRM_ПРОРАБ}}", "role_in_project": "foreman"},
    {"worker_name": "{{UF_CRM_МЕНЕДЖЕР_ПРОЕКТА}}", "role_in_project": "pm"},
    {"worker_name": "{{UF_CRM_СМЕТЧИК}}", "role_in_project": "estimator"},
    {"worker_name": "{{UF_CRM_ПРОДАВЕЦ}}", "role_in_project": "sales"}
  ]
}
```

> **Важно:** Коды полей (UF_CRM_...) в твоём Битрикс24 могут отличаться! Чтобы узнать точный код поля:
> - В карточке сделки нажми на шестерёнку ⚙️ рядом с полем
> - Или: Настройки → Пользовательские поля → посмотри колонку "Код"
> - В интерфейсе роботов можно кликнуть на кнопку **"..."** чтобы выбрать поле из списка

4. Нажми **Сохранить**

### Шаг 3.3: Добавить второй робот — записать URL'ы из ответа

1. Добавь ещё один робот на **той же стадии**, после первого
2. Выбери **"Изменить элемент"** (Change item / Modify deal)
3. Настрой:
   - Поле `Google Drive URL` = `{{Результат предыдущего действия.google_drive_url}}`
   - Поле `Google Sheets URL` = `{{Результат предыдущего действия.google_sheets_url}}`
   - Поле `Отправлено в реестр` = Да

> **Примечание:** синтаксис подстановки результата зависит от версии Битрикс24. Возможные варианты:
> - `{{~A1.google_drive_url}}` (где A1 — ID первого робота)
> - `{{Результат.Body.google_drive_url}}`
> - Может потребоваться парсинг JSON через дополнительное действие

4. Добавь **условие**: выполнять только если `Google Drive URL` **пусто** (чтобы не перезаписывать на повторных сохранениях)

5. Нажми **Сохранить**

## Часть 4: Робот для синхронизации работников (3 мин)

### Что делаем:
При изменении профиля сотрудника (Telegram ID заполнен) — дёргаем webhook чтобы обновить реестр работников.

### Проблема:
В облачном Битрикс24 **нет** роботов для события "изменение профиля сотрудника". Это можно сделать только через:
- **REST API + подписка на событие** (нужно локальное приложение)
- **Ручной вызов curl** (для теста)

### Решение для теста: curl

```bash
curl -X POST http://localhost:3000 \
  -H "Content-Type: application/json" \
  -d '{
    "secret": "foremen-apps-script-secret-2024",
    "action": "upsert_worker",
    "bitrix_user_id": "1",
    "worker_name": "Alexander Borohov",
    "role": "admin",
    "telegram_id": 571744833
  }'
```

### Решение для продакшена:
Создать **Локальное приложение** (см. Часть 7) которое подписано на событие `ONUSERUPDATE`.

## Часть 6: Когда робот Битрикс24 не может отправить webhook

Если робот "Запрос по URL" не отправляет JSON как надо (бывает в некоторых тарифах), есть альтернативы:

### Альтернатива A: Входящий webhook + скрипт

1. Создай **Входящий webhook** (Разработчикам → Другое → Входящий вебхук)
2. Напиши простой скрипт который:
   - Берёт данные сделки через REST API (`crm.deal.get`)
   - Отправляет их на наш webhook
   - Записывает URL'ы обратно (`crm.deal.update`)

### Альтернатива B: Кнопка в карточке сделки

Добавь кнопку (через бизнес-процесс или действие) которая запускает скрипт синхронизации — менеджер нажимает после заполнения сделки.

### Альтернатива C: Polling-скрипт

Крон-скрипт (раз в 5 мин) проверяет все сделки где `Отправлено в реестр = Нет` и дёргает webhook для каждой.

## Часть 7: Локальное приложение для автоматизации (продакшен)

Для полной автоматизации без ручных curl'ов нужно:

1. В **Разработчикам** → **Готовые сценарии** → **Другое** → **Локальное приложение** (Local app)
2. Создай приложение:
   - Название: `Foremen Bot Sync`
   - Тип: **Серверное**
   - URL обработчика: URL Cloud Function `bitrix-webhook`
   - Права (scopes): ☑ CRM, ☑ Пользователи, ☑ Рабочие группы
3. Подпишись на события:
   - `ONCRMDEALADD` — создание сделки
   - `ONCRMDEALUPDATE` — обновление сделки
   - `ONUSERUPDATE` — изменение сотрудника
4. Приложение будет получать уведомления о каждом изменении

> Это — финальный шаг для продакшена. Для тестирования достаточно curl'ов из Части 5.
