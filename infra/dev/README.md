# Foremen — DEV environment on Google Cloud

A cheap, single-VM dev environment that runs the whole app stack with
`docker compose` (frontend + backend + Liquibase + Postgres), exactly like the
local setup. The database is a Postgres **container on the VM** (the cheapest
option). The app is reached over the VM's public hostname — **no custom domain,
no TLS** for now:

```
http://<STATIC_IP>/                      # or
http://<STATIC_IP-with-dashes>.bc.googleusercontent.com/
```

The frontend container serves the SPA and proxies `/api` to the backend, so
there is nothing to configure per-IP and no CORS concerns.

> These scripts create **paid** cloud resources. Nothing runs automatically —
> you execute the numbered scripts yourself, in order.

## What gets created (project `starry-tracker-505110-s3`, region `europe-central2`)

| Resource | Purpose | Rough cost |
|----------|---------|-----------|
| Compute Engine `e2-small` VM + 20 GB disk | runs the whole stack | ~$13–15/mo 24×7 (less if stopped nights) |
| Static external IP | stable public hostname | free while attached to a running VM |
| Firewall rule (tcp:80) | public web access | free |
| Artifact Registry repo | holds the two images | pennies |
| Secret Manager (3 secrets) | DB / JWT / admin passwords | pennies |
| Service account | least-privilege VM identity | free |

No Cloud SQL by default (an optional switch is provided).

## Prerequisites

- `gcloud` authenticated as a user with Owner/Editor on the project (you are:
  `info@foremen.eu`).
- Docker with `buildx` locally to build and push images (or use the optional
  Cloud Build script).
- Review `config.env` and adjust if needed.

## Run order

```bash
cd infra/dev
# 1. one-time project setup
./10-enable-apis.sh
./20-secrets.sh
./30-artifact-registry.sh

# 2. build & push images (linux/amd64)
./40-build-push.sh

# 3. create the VM and bring the stack up
./50-vm.sh         # prints the public URL + how to read the admin password

# later: after pushing new images
./55-redeploy.sh

# optional cost saver: stop at night, start weekday mornings
./60-schedule.optional.sh

# tear everything down (prompts; DELETES dev data)
./90-destroy.sh            # add --all to also remove secrets + AR repo
```

## First login

```bash
# admin email is in config.env (ADMIN_EMAIL); password:
gcloud secrets versions access latest --secret=foremen-dev-db-password   # DB
gcloud secrets versions access latest --secret=foremen-dev-admin-password # app admin
```

## Operating the VM

```bash
# SSH in
gcloud compute ssh foremen-dev --zone=europe-central2-a

# logs
sudo tail -f /var/log/foremen-startup.log
cd /opt/foremen && docker compose -f docker-compose.dev.yml logs -f backend

# restart the stack
cd /opt/foremen && docker compose -f docker-compose.dev.yml --env-file .env up -d
```

## Known limitations / notes

- **No HTTPS.** `*.bc.googleusercontent.com` and bare IPs cannot get a
  Let's Encrypt / managed certificate, so dev is HTTP only. Logins travel in the
  clear and the browser shows "not secure". When you want TLS, switch to
  `dev.foremen.eu`: add a DNS record at **home.pl** (the zone's current
  nameservers are `dns.home.pl`), then add nginx + a certificate. The stack does
  not need rebuilding for that.
- **Data lives on the VM disk.** The Postgres volume is on the VM. Deleting the
  VM (via `90-destroy.sh`) destroys the dev data. Switch to Cloud SQL
  (`15-cloud-sql.optional.sh`) if you need managed, backed-up storage.
- **Secrets** are generated by `20-secrets.sh` and stored only in Secret Manager
  — never in git. The VM reads them at boot via its service account.
- **Mail / Google keys** default to disabled/empty for dev. Set real values on
  the VM's `/opt/foremen/.env` (and in Secret Manager if you prefer) when needed.
- **Cost control.** Use `60-schedule.optional.sh`, or just
  `gcloud compute instances stop foremen-dev --zone=europe-central2-a` when idle.
