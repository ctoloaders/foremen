# Тест-кейсы: FOR-05-05 — Смета (вкладка «Смета / Kosztorys»), матрица работ × помещений

> Документ следует стандарту `.kiro/steering/test-cases.md`. Спека **полностековая**: часть
> сценариев исполняется браузерным движком (UI вкладки «Смета»), часть — как API-тесты против
> поднятого в Docker приложения. Артефакты прогонов — **MD-репорты с таблицами** (не скриншоты).
> Покрываемые требования: 1.1–1.6, 2.1–2.5, 3.1–3.5, 4.1–4.4, 5.1–5.4, 6.1–6.6, 7.1–7.3, 8.1–8.5,

> 18.1–18.3, 19.1–19.4.

## Окружение и запуск

### Docker-стек
- В корне проекта: `docker compose up` поднимает `postgres` (:5432), `liquibase` (миграции),
  `backend` (:8080, профиль `docker`), `frontend` (:3000).
- Базовый URL API: `http://localhost:8080`. Auth-эндпоинты — под `/api/auth`.
- Первый ADMIN создаётся через `FOREMEN_ADMIN_CREATE=true`, `FOREMEN_ADMIN_EMAIL`,
  `FOREMEN_ADMIN_PASSWORD`.
- UI: `http://localhost:3000`, вкладка проекта `/projects/:projectId` → «Смета / Kosztorys».

### Эндпоинты в фокусе
| Метод | Путь | ABAC | Персистит? |
|-------|------|------|-----------|
| GET  | `/api/estimates/project/{projectId}/matrix` | ESTIMATE READ | нет (чтение) |
| POST | `/api/estimates/project/{projectId}/apply-package` | ESTIMATE READ | нет (calculate/preview) |
| POST | `/api/estimates/project/{projectId}/apply-work` | ESTIMATE READ | нет (calculate/preview) |
| POST | `/api/estimates/project/{projectId}/recompute-finishing` | ESTIMATE READ | нет (calculate/preview) |
| POST | `/api/estimates/project/{projectId}/assignments` | ESTIMATE **UPDATE** | да (батч-Save) |

### Стратегия повторяемости (обязательно)
Единая для всего документа:
- **Генератор данных.** На каждый прогон формируется `run-id` = UNIX-timestamp или UUID.
  Все создаваемые сущности получают уникальные имена/коды с суффиксом `run-id`
  (проект `E2E Смета {run-id}`, пользователи `estimate.reader+{run-id}@example.com` /
  `estimate.editor+{run-id}@example.com`). Это исключает коллизии при повторных прогонах.
- **Teardown.** В конце каждого набора — явный шаг: проект переводится из DRAFT в архив/удаляется
  (или деактивируются созданные пользователи), staged-edits в `localStorage` очищаются
  (Discard либо `localStorage.removeItem('foremen.estimateMatrix.<projectId>')`).
- Матрица не требует ручной чистки БД между прогонами: каждый прогон работает в своём проекте
  `{run-id}`, а правки до Save живут только в `localStorage`.
- Миграции `102`–`104` идемпотентны, поэтому повторный `docker compose up` безопасен.

### Предпосылки на данные (общий Setup, выполняется один раз на прогон)
1. Аутентифицироваться ADMIN (`POST /api/auth/login`), получить access-токен.
2. Создать проект `E2E Смета {run-id}` в статусе **DRAFT**.
3. Добавить в проект ≥2 помещения с заполненными 14 измерениями (например, «Кухня», «Ванная»)
   и разными типами помещений (для проверки Room_Type_Attachment).
4. Убедиться, что в каталоге есть ≥1 группа работ (Work_Type_Group), работы с формулой объёма,
   работа без формулы (для fallback), работа с непустым Room_Type_Attachment, а также пакеты
   (`budget`/`norm`/`lux`) с участниками и позициями ассортимента.
5. Создать двух пользователей: **reader** (ESTIMATE READ, без UPDATE) и **editor**
   (ESTIMATE READ+UPDATE), назначить их на проект.
