# Тест-кейсы: FOR-05-02c — ручные пропуски и размеры проёмов в комнате с геометрией

Спека: `FOR-05-02c-bugfix-room-manual-dimensions` (bugfix). Документ написан по стандарту `.kiro/steering/test-cases.md`.

Покрываемые требования: 1.1–1.6, 2.1–2.8, 3.1–3.8 из `bugfix.md`.

Что проверяем (кратко):

- Корневые `wallGap` / `finishGap` комнаты с геометрией, помеченные `MANUAL`, сохраняются и не затираются суммой пропусков по стенам. `wallArea` считается от эффективных пропусков.
- Без ручного значения (источник не передан или `CALCULATED`, значение `null`) пропуск равен сумме по стенам, источник `CALCULATED`.
- Размеры `doorHeight`, `doorWidth`, `windowHeight`, `windowWidth`: ровно один проём типа (сумма `count` = 1) даёт его размер, больше одного даёт `null` (в матрице «—»). Ручной размер (`MANUAL`) побеждает геометрию. Очистка ячейки возвращает `CALCULATED`.
- Пояснение периметра: формула `wall1 + … + wallN`. Если задана `dimensionFormulas["geometry.walls[i].length"]`, вместо `wall{i+1}` показывается текст формулы. Показывается в поповере ячейки периметра.
- Фронтенд отправляет `MANUAL` для отредактированных пропусков и размеров и повторно отправляет сохранённые `MANUAL`-источники.
- Миграция: Liquibase-чейнджсет **266** (`266-room-manual-dimension-sources.xml`) добавляет шесть колонок `wall_gap_source`, `finish_gap_source`, `door_height_source`, `door_width_source`, `window_height_source`, `window_width_source` (`VARCHAR(20)`, nullable) и backfill `CALCULATED`. Если при реализации номер был сдвинут (266 занят), в отчёте прогона указать фактический номер.

Результат прогона — MD-репорт с таблицами (шаблон в конце файла). Скриншоты не требуются.

## 0. Окружение и общие правила

### 0.1. Запуск окружения

```
docker compose up -d --build        # postgres :5432, liquibase, backend :8080 (профиль docker), frontend :3000
```

Первый ADMIN создаётся переменными `FOREMEN_ADMIN_CREATE=true`, `FOREMEN_ADMIN_EMAIL`, `FOREMEN_ADMIN_PASSWORD` (значения берутся из `.env`). Базовый URL API: `http://localhost:8080`. Базовый URL UI: `http://localhost:3000`.

Предусловие окружения (проверяется один раз перед прогоном):

| # | Проверка | Ожидание |
|---|----------|----------|
| E1 | `GET http://localhost:8080/actuator/health` (или любой публичный эндпоинт) | 200, бэкенд поднят |
| E2 | В таблице `databasechangelog` есть запись для `266-room-manual-dimension-sources.xml` (оба changeSet выполнены или `MARK_RAN`) | запись есть |
| E3 | В таблице `rooms` есть шесть колонок `*_source` для пропусков и размеров | колонки есть |

### 0.2. Стратегия повторяемости

**Генератор данных + Setup + Teardown.**

- `RUN_ID` = `YYYYMMDDHHmmss` (или короткий uuid), один на весь прогон.
- Setup (один раз на прогон, шаг S1–S4 ниже): через API создаются **проект `FOR-05-02c {RUN_ID}`** и комнаты с суффиксом `{RUN_ID}` в `label`. Ничего из существующих данных (в том числе проект 1531 и комната 1701) не изменяется.
- Каждый тест-кейс работает со своей комнатой (создаётся в начале кейса, id сохраняется в переменную `ROOM_<TC>`), поэтому кейсы независимы и запускаются в любом порядке.
- Teardown (Т1–Т2 в конце): удаление всех созданных комнат (`DELETE /api/rooms/{id}`, либо `deleteIds` в save) и проекта. Teardown выполняется даже при падении кейсов.
- Ручная чистка БД между прогонами не нужна.

### 0.4. Шаблоны данных

**Прямоугольник 3.0 × 2.11** (периметр 10.22, площадь пола 6.33). Вершины по часовой стрелке:

```json
"geometry": {
  "vertices": [{"x":0,"y":0},{"x":3.0,"y":0},{"x":3.0,"y":2.11},{"x":0,"y":2.11}],
  "walls": [
    {"wallGap": null, "finishGap": null, "openings": [{"type":"DOOR","count":1,"height":2.0,"width":0.58}]},
    {"wallGap": null, "finishGap": null, "openings": []},
    {"wallGap": null, "finishGap": null, "openings": []},
    {"wallGap": null, "finishGap": null, "openings": []}
  ]
}
```

Это геометрия комнаты 1701 «Przedpokój»: одна дверь 0.58 × 2.0 (площадь двери 1.16). Высота потолка `ceilingHeight = 2.7`.

Расчёт эталона room-1701: `wallArea = (10.22 − 3 − 2) × 2.7 − 1.16 = 14.094 − 1.16 = 12.934 → 12.93`. Без ручных пропусков: `(10.22 − 0 − 0) × 2.7 − 1.16 = 26.434 → 26.43`.

**Тело save-запроса** (`POST /api/rooms/project/{PROJECT_ID}/save?force=false`):

```json
{
  "createList": [ { "projectId": PROJECT_ID, "roomTypeId": ROOM_TYPE_ID, "label": "...{RUN_ID}", "ceilingHeight": 2.7, "geometry": {...}, "wallGap": 2, "wallGapSource": "MANUAL", "finishGap": 3, "finishGapSource": "MANUAL", "wallArea": 12.93 } ],
  "updateItems": [ { "id": ROOM_ID, "data": { ...поля комнаты... } } ],
  "deleteIds": []
}
```

Чтение результата после save: `GET /api/rooms/{ROOM_ID}` (расширенный DTO с `wallGap`, `wallGapSource`, `finishGap`, `finishGapSource`, `wallArea`, `wallAreaSource`, `perimeter`, `doorArea`, `doorHeight`, `doorHeightSource`, `doorWidth`, `doorWidthSource`, `windowHeight`, `windowHeightSource`, `windowWidth`, `windowWidthSource`, `explanations`/пояснения метрик). Название поля с пояснением периметра брать по фактическому контракту DTO (`perimeter` в карте пояснений).

> Допуск при сравнении денежно-площадных значений: ±0.01. Идентификаторы комнат подставляются из ответов, их нельзя хардкодить.

Для проверки значений в БД (по желанию, дополнительно к API):

```sql
SELECT wall_gap, wall_gap_source, finish_gap, finish_gap_source, wall_area,
       door_height, door_height_source, door_width, door_width_source
FROM rooms WHERE id = :ROOM_ID;
```

Покрыто TC-A4-01: значения пропусков и размеров сохраняются как отправлены, `wallArea` считается по формуле плоской комнаты. Шаги выполнить повторно вместе с проверкой `floorArea`, `perimeter`, `doorCount`, `windowCount`: эти значения равны отправленным.

### TC-R-02. Пропуски по стенам без ручного корневого значения (Req 3.2)

### TC-R-05. Счётчики и площади по геометрии при единственном проёме (Req 3.5)

Покрыто TC-A2-01, TC-A2-02: `doorCount`, `windowCount`, `doorArea`, `windowArea`, `floorArea`, `perimeter` равны значениям из геометрии. Новые размеры добавляются только к ним и не меняют остальное.

Покрыто TC-B2-04: «Площадь стен», «Площадь дверей», «Площадь окон» показывают формулу и значение под каждым элементом, как до исправления.
