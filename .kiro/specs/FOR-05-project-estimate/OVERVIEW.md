# FOR-05: Проект в стадии проектирования (DRAFT) / Project in design (DRAFT) stage

## Обзор

FOR-05 — родительская спека **стадии проектирования проекта** (проект в статусе `DRAFT`,
до подписания договора). Она объединяет всю подготовительную работу над ремонтным проектом
в **единое пространство проекта**: один пункт меню (**Проекты → открыть проект**) ведёт на
страницу проекта, где этапы проектирования — это табы внутри одного контекста. В шапке
проектной стадии виден **трекер готовности проекта к подписанию**.

> **Граница ответственности (важно):** FOR-05 покрывает **только** то, что происходит,
> пока проект в `DRAFT` — подготовка оффера, подготовка и подписание документов, подбор
> команды, планировочный Гант (эстимация) и трекер готовности. **Всё, что происходит после
> подписания договора** (проект «в работе»/`ACTIVE`) — подготовка и подписание амендментов,
> отчётность работников, обновление графика-Ганта, трекинг закупок — вынесено в
> **FOR-06 «Проект в работе» (`FOR-06-project-in-progress`)**. См. раздел
> «Переход FOR-05 → FOR-06».

Источник правды для доменной модели — текущий Excel клиента
(`docs/Matrix Foremen v3.0 (1).xlsx`, лист `Oferta`): один лист содержит весь проект —
список работ по категориям, количества по комнатам, спецификацию материалов с нормами
расхода, три коммерческих пакета (START / COMFORT / PRESTIGE), маржу (план/факт),
изменения (амендменты) и понедельный прогресс работников. Амендменты и прогресс работников
— это уже **стадия исполнения** и живут в FOR-06.

Полный технический анализ (эргономика UI/UX, доменная модель, ABAC-матрица, алгоритмы,
управление ценами, e-подпись по польскому праву) находится в `design.md` этой же папки.
Настоящий OVERVIEW — навигационная карта: он фиксирует **список дочерних спек FOR-05-NN** и
их зависимости. Каждая дочерняя спека далее прорабатывается как отдельная спека (свои
`requirements.md` / `design.md` / `tasks.md` / `test-cases.md`).

## Кликабельный прототип

Готовый статичный HTML-прототип страницы проекта (для демонстрации клиенту) лежит рядом:

- **`prototype/project-workspace.html`** — открывается в браузере без сборки. Показывает
  все предложенные UI/UX-принципы: единое пространство с табами, виджет готовности в шапке,
  плотные таблицы на десктопе / карточки на мобиле, прогрессивное раскрытие деталей строки
  сметы, пакеты START/COMFORT/PRESTIGE и мок-флоу подписания. Данные захардкожены из
  Excel-оферты. (Прототип покрывает обе стадии для демо; за реализацию стадии исполнения
  отвечает FOR-06.)

## Ключевые UI/UX-принципы (из design.md §1)

| Принцип | Решение |
|---------|---------|
| Один проект — один контекст | Единый роут `/projects/:projectId` + локальные табы, без ухода из проекта |
| Мобайл-ферст, мало верхнеуровневых выборов | Этапы сгруппированы в фазы; на мобиле — сегмент-контрол + overflow |
| Прогрессивное раскрытие | Матрица по комнатам, BoM, маржа — за раскрывашкой/в drawer, не в основной сетке |
| Отслеживание готовности | Постоянный виджет готовности в шапке (done/partial/blocked + общий %) |
| Плотные данные | Таблицы для сравнения на десктопе, карточки на мобиле, графики — как сводка |

## Табы стадии проектирования (DRAFT)

Набор табов зависит от стадии проекта (`Project.status`), граница — подписание договора.
**FOR-05 владеет табами стадии проектирования.** Табы стадии исполнения — FOR-06.

| Таб стадии проектирования (FOR-05, до подписания) | Назначение |
|---------------------------------------------------|------------|
| Обзор | Сводка/паспорт проекта, поля проекта (вторичное редактирование) |
| Трекер готовности | Готовность проекта к подписанию (done/partial/blocked + %) |
| Расценки (Cennik) | Каталожные/проектные цены работ, база оффера |
| Комнаты (Pomieszczenia) | Матрица «размеры × помещения», геометрия комнат |
| Смета — объёмы + виды работ (Kosztorys) | Интерактивная матрица «виды работ × комнаты» + BoM/материалы |
| Оффер / согласование (Oferta) | Пакеты, скидки/ребейты, отправка и согласование оффера |
| История цен (Historia cen) | Read-only прозрачность изменений цен (каталог/проект/работник) |
| Эстимация-Гант (Harmonogram) | Планировочный Гант — оценка сроков до старта работ |
| Документы: подготовка (Dokumenty) | Бланки/шаблоны документов (договор и приложения) |
| Подписание документов (Podpisanie) | E-подпись документов проектной стадии (договор и т.п.) |
| Команда (Zespół) | Подбор и назначение команды на проект |

> Табы стадии исполнения (Закупки, Первичные документы, План/факт Гант, Расчёт ЗП,
> Подписание амендментов) переезжают в **FOR-06 «Проект в работе»**.

## Управление ценами (из design.md §4.3a–4.7, §6.6–6.9)

Ценообразование целиком относится к подготовке оффера и потому остаётся в FOR-05
(за исключением ценовых дельт амендментов, которые применяются уже в стадии исполнения —
FOR-06 читает проектные цены FOR-05 и добавляет `AMENDMENT`-оверрайды).

| Аспект | Модель |
|--------|--------|
| **Каталожная цена работы** | Единая цена работы `(workItem, currency, netPrice)` без пакетов (после FOR-05-04). Владелец каталожной цены — FOR-04-12 |
| **Фиксация цены оффера** | Цена из прейскуранта замораживается в `EstimateLine.unitPrice`; при APPROVED/SIGNED — снапшот в `OfferPriceSnapshot`, подписанный оффер не меняется от правок каталога |
| **Временны́е цены на проекте** | `ProjectServicePrice` — интервалы `[effectiveFrom, effectiveTo)`; `OFFER_BASE` (с даты подписания). **`AMENDMENT`-оверрайды создаются в стадии исполнения (FOR-06)**, но пишутся в ту же таблицу проектных цен, которой владеет FOR-05 |
| **Внутренняя расценка работнику** | `WorkerServiceRate` — временна́я и пер-работник; **владение и расчёт выплат — FOR-10/FOR-11**; FOR-05 только определяет модель для целостности |
| **Прозрачность изменений цен** | Read-only вью для ADMIN + FINANCIER (`PRICE_HISTORY`) поверх аудита + временны́х таблиц. Часть подготовки оффера (история и обоснование цен), остаётся в FOR-05 |

## Переход FOR-05 → FOR-06 (граница «подписан договор»)

Подписание договора (FOR-05-08) переводит проект из `DRAFT` в стадию исполнения.
С этого момента активируются спеки FOR-06:

| Активность стадии исполнения | Спека | Что читает из FOR-05 |
|------------------------------|-------|----------------------|
| Подготовка амендментов (изменения объёмов, дат, цен) | FOR-06 | Смету (03/05), проектные цены (13), подписываемые документы (08) |
| Подписание амендментов | FOR-06 | Движок `SignableDocument`/`DocumentSignature` (08) |
| Отчётность работников (WorkReport + аппрув) | FOR-06 | `resolveClientPrice` (13), состав работ/смету (03/05) |
| Обновление Гант-графика (авто из отчётности, ручное из амендментов) | FOR-06 | Планировочный Гант (15), отчётность и амендменты FOR-06 |
| Трекинг закупок | FOR-06 | Смету/BoM (05) как источник потребности |
