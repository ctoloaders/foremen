# Тест-кейсы: FOR-05-06 — Packages & margins (модель себестоимости)

Документ описывает ручные/автоматизируемые тест-кейсы для спеки **FOR-05-06-packages-margins**.
Спека имеет два типа поверхностей, поэтому кейсы разделены:

- **API-кейсы** — HTTP-запросы против поднятого в Docker приложения (эндпоинт маржи, CRUD
  WorkerType, персистентность `cost_net`, миграции 125–127). Исполняются движком API-тестов, артефакт
  прогона — MD-репорт с таблицами.
- **UI-кейсы** — сценарии в браузерном движке (вкладка «Маржа / Marża», админ-CRUD WorkerType, поля
  `cost_net` в формах материалов). Исполняются headless-браузером, артефакт прогона — MD-репорт с
  таблицами (без скриншотов).

Ссылки на требования указаны в каждом кейсе (`R<номер>.<критерий>`).

---

## Общие предусловия и окружение

### Поднятие окружения (Docker-стек)

1. В корне репозитория выполнить `docker compose up`. Поднимаются:
   - `postgres` (`:5432`),
   - `liquibase` (применяет миграции, включая `125`, `126`, `127`),
   - `backend` (`:8080`, профиль `docker`),
   - `frontend` (`:3000`).
2. Первый ADMIN создаётся переменными окружения:
   `FOREMEN_ADMIN_CREATE=true`, `FOREMEN_ADMIN_EMAIL`, `FOREMEN_ADMIN_PASSWORD`.
3. Базовый URL для API-тестов: `http://localhost:8080`. Auth-эндпоинты — под `/api/auth`.
4. Базовый URL для UI-тестов: `http://localhost:3000`.

### Получение токена (общий шаг для API-кейсов)

- `POST /api/auth/login` с телом `{ "email": "<FOREMEN_ADMIN_EMAIL>", "password": "<FOREMEN_ADMIN_PASSWORD>" }`
  → `200` + `accessToken`. Токен подставляется в заголовок `Authorization: Bearer <accessToken>`
  во все последующие запросы.

### Соглашение о `run-id`

Во всех наборах, где создаются сущности, используется `run-id` — уникальный суффикс на прогон
(timestamp или UUID, например `20250115-103245` либо `9f3c…`). Он подставляется в поля `code`
(и подобные), чтобы прогоны не конфликтовали по уникальным ключам.

## Фича D. Эндпоинт маржи `GET /api/estimates/project/{id}/margins` (API)

**Стратегия повторяемости:** только READ над проектом/сметой (get-or-create кошториса не мутирует
пользовательских данных). Для проекта без сметы отдельная чистка не нужна. Если для наполнения строк
создавались временные проектные данные — использовать проект с `run-id` и teardown в конце.

### TC-D1 — Чтение маржи по проекту со сметой: группировка и тир-столбцы

- **Требования:** R4.1, R4.2, R4.3, R5.1
- **Предусловия:** ADMIN-токен; есть проект `projId` в стадии DRAFT со сметой (работы + материалы,
  ненулевые offer-цены).
- **Шаги:**
  1. `GET /api/estimates/project/{projId}/margins`.
     - Ожидание: `200`; в ответе `projectId = projId`, массив `workerTypes` (упорядоченные тиры),
       `groups` (строки, сгруппированные по типу работ), `dashboard`.
  2. Проверить порядок и число тиров в `workerTypes`.
     - Ожидание: совпадает с порядком справочника (`orderNo`), базовый тир помечен `base = true`.
  3. Взять одну строку работы с ненулевым `offerPrice`; проверить `baseCost` и `tierCosts`.
     - Ожидание: `baseCost = round(0.40 × offerPrice, 0.5)`; `tierCost(base) = baseCost`;
       `tierCost(t) = baseCost × (1 + upliftt)` для небазовых тиров.

### TC-D2 — Себестоимость считается на лету (меняется вместе с offer)

- **Требования:** R2.1, R2.2, R2.3, R2.5
- **Предусловия:** проект `projId` со сметой; известна работа с настраиваемой offer-ценой.
- **Шаги:**
  1. `GET .../margins`; запомнить `baseCost` и `tierCosts` строки.
  2. Изменить offer-цену работы (через соответствующий эндпоинт цен работ).
     - Ожидание: `200`.
  3. Повторно `GET .../margins`.
     - Ожидание: `baseCost` и `tierCosts` пересчитаны от новой цены (ничего не закешировано/не
       сохранено как себестоимость); округление base — до ближайших 0.5 zł (half-up).

### TC-D3 — Раздельная маржа: труд vs материалы по бранчам

- **Требования:** R4.4, R5.3
- **Предусловия:** проект `projId` со сметой, где у работы выбраны и строительные, и отделочные
  материалы с известными `retailNet`/`costNet`.
- **Шаги:**
  1. `GET .../margins`.
     - Ожидание: в строке присутствуют отдельные поля `construction` и `finishing`
       (`retailTotal`, `costTotal`, `margin`), не слитые с трудовой маржой.
  2. Проверить трудовую маржу: `minProfit`, `avgProfit`, `maxProfit` по тирам.
     - Ожидание: `maxProfit` — на базовом тире (минимальная стоимость), `minProfit` — на самом
       дорогом тире (`FIRM`), `avgProfit` — среднее по тирам; каждая маржа = `offer − tierCost`.
  3. Проверить материальную маржу по бранчам.
     - Ожидание: `margin = retailTotal − costTotal` независимо для construction и finishing.

### TC-D4 — Дашборд = сумма строк

- **Требования:** R5.2, R5.3
- **Предусловия:** проект `projId` со сметой (несколько строк).
- **Шаги:**
  1. `GET .../margins`; для каждого тира просуммировать по строкам `tierCost` и трудовую маржу.
     - Ожидание: `dashboard.labourByTier[t].costTotal` = Σ построчных `tierCost` для тира `t`;
       `margin` = Σ построчных трудовых марж.
  2. Просуммировать по строкам `construction`/`finishing` retail и cost.
     - Ожидание: `dashboard.constructionTotal` и `dashboard.finishingTotal` равны суммам по строкам.

### TC-D5 — Недоступность распространяется (null offer ⇒ «—», исключение из тоталов)

- **Требования:** R2.4, R4.5, R5.4
- **Предусловия:** проект со сметой, где хотя бы у одной работы нет offer-цены (null/0).
- **Шаги:**
  1. `GET .../margins`.
     - Ожидание: у строки без цены `baseCost = null` и `tierCosts[*].cost = null`,
       `margin.amount = null` (в UI отрисуется `—`).
  2. Проверить дашборд.
     - Ожидание: строка без цены исключена из тоталов (никаких «0-производных» марж); материалы с
       null retail/cost также исключены из материальных тоталов.

### TC-D6 — Проект без сметы возвращает пустую структуру (не 404)

- **Требования:** R4.1, R5.1
- **Предусловия:** проект `projEmpty` без созданной сметы.
- **Шаги:**
  1. `GET /api/estimates/project/{projEmpty}/margins`.
     - Ожидание: `200` с пустой структурой (`groups = []`), а не `404` (используется get-or-create
       кошториса, как в FOR-05-05b).

### TC-D7 — ABAC: чтение маржи требует ESTIMATE READ

- **Требования:** R4.1
- **Предусловия:** пользователь без права READ на `ESTIMATE`.
- **Шаги:**
  1. Без токена `GET .../margins` → `401`.
  2. Токеном без ESTIMATE READ → `403`.
