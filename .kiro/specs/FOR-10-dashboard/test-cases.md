# Тест-кейсы: FOR-10 — Настраиваемая панель (Dashboard)

Спека содержит и браузерные экраны (Panel, админка виджетов), и API. Поэтому:
- **Часть A — API-тесты** против работающего Docker-стека (`http://localhost:8080`).
- **Часть B — UI-сценарии**, исполняются браузерным движком (headless). Скриншоты не требуются.
- Результат прогона — MD-репорт с таблицами (шаблон в конце файла).

## Окружение и стратегия повторяемости

Окружение: `docker compose up` (postgres :5432, liquibase, backend :8080 профиль `docker`, frontend :3000).
Первый ADMIN: `FOREMEN_ADMIN_CREATE=true`, `FOREMEN_ADMIN_EMAIL`, `FOREMEN_ADMIN_PASSWORD`.
Для AI-кейсов: `FOREMEN_DASHBOARD_AI_ENABLED=true`, `FOREMEN_DASHBOARD_AI_LLM_STUB=true`.

**Стратегия повторяемости: генератор данных + teardown.**
- `run-id` = `yyyyMMddHHmmss` + 4 случайных символа. Все создаваемые сущности именуются с `run-id`:
  пользователи `dash+{run-id}-{role}@example.com`, проекты `DASH-{run-id}-A/B`, виджеты `TC_{RUN_ID}_*`
  (код в верхнем регистре, `RUN_ID` без дефисов).
- Teardown (выполняется всегда, даже при падении): удалить размещения тестовых пользователей,
  деактивировать и удалить тестовые виджеты (`DELETE /api/dashboard-widgets/{id}`), деактивировать
  тестовых пользователей и проекты (через существующие admin-эндпоинты).
- Сидовые виджеты и дефолты ролей тестами НЕ изменяются; тесты, меняющие матрицу прав, создают
  собственную тестовую роль `DASH_{RUN_ID}` и удаляют её в teardown.

**Общие предусловия (Setup):** токен ADMIN; пользователи по ролям MANAGER, FOREMAN, WORKER, FINANCIER,
CLIENT (создаются через admin API, при создании им должны быть выданы дефолтные виджеты); два проекта
`A` и `B` в статусе ACTIVE; пользователь WORKER и MANAGER добавлены в проект A; CLIENT добавлен в проект A.

# Часть A. API

## A1. Макет и размещение (Layout)

### TC-A1-01 Дефолтный макет нового пользователя
- Предусловия: Setup.
- Шаги:
  1. Создать пользователя MANAGER `dash+{run-id}-mgr`. Ожидание: 201.
  2. Логин, `GET /api/dashboard`. Ожидание: 200, items = дефолты MANAGER (`ACTIVE_PROJECTS`@0, `PAYMENTS_RECEIVED`@12, `WORK_REPORTS_PENDING`@14, `PAYMENTS_BY_PROJECT`@16, `OFFERS_BY_STATUS`@24), порядок по `cellIndex`, у всех `state=AVAILABLE`.
  3. Повторить шаг 2. Ожидание: тот же набор (повторный вызов не дублирует сид).

### TC-A1-02 Пользователь, удаливший все виджеты, не получает сид повторно
- Шаги: 1) DELETE всех items пользователя. 2) `GET /api/dashboard`. Ожидание: `items=[]`.

### TC-A1-03 Добавление виджета в первую подходящую позицию
- Предусловия: пустой дашборд (TC-A1-02).
- Шаги:
  1. `POST /api/dashboard/items {widgetId: <PAYMENTS_RECEIVED>}`. Ожидание: 201, `cellIndex=0`.
  2. `POST` виджета 2x2 (`WORK_REPORTS_BY_STATUS`) без cellIndex. Ожидание: 201, `cellIndex=1`.
  3. `GET /api/dashboard`. Ожидание: два элемента, порядок по cellIndex.

### TC-A1-04 Добавление в конкретную ячейку и проверка границ
- Шаги:
  1. `POST` 2x2-виджета с `cellIndex=3` (колонка 3, ширина 2 выходит за 4). Ожидание: 400 `error.dashboard.cell.invalid`.
  2. `POST` 1x1-виджета с `cellIndex=36`. Ожидание: 400 `error.dashboard.cell.invalid`.
  3. `POST` 2x2-виджета с `cellIndex=33` (строка 8, высота 2 выходит за 9). Ожидание: 400.

### TC-A1-05 Перекрытие многоклеточных виджетов
- Шаги: 1) Разместить 2x2 в `cellIndex=0`. 2) `POST` 1x1 в `cellIndex=5` (внутри футпринта). Ожидание: 409 `error.dashboard.cell.occupied`. 3) `POST` 1x1 в `cellIndex=2`. Ожидание: 201.

### TC-A1-06 Заполнение сетки
- Шаги: 1) Заполнить сетку виджетами 4x3, 4x3, 4x3 (строки 0-8). 2) `POST` любого виджета. Ожидание: 409 `error.dashboard.grid.full`.

### TC-A1-07 Дубликаты
- Шаги: 1) Добавить `PAYMENTS_RECEIVED`. 2) Добавить его же снова. Ожидание: 409 `error.dashboard.widget.duplicate`.
  3) Добавить `PROJECT_CARD` для проекта A. Ожидание: 201. 4) `PROJECT_CARD` для проекта B. Ожидание: 201.
  5) `PROJECT_CARD` для проекта A повторно. Ожидание: 409 duplicate.

### TC-A1-08 Удаление и изоляция владельцев
- Шаги: 1) Пользователь U1 удаляет свой item. Ожидание: 204. 2) U2 пытается `DELETE` item U1 / читать `/data` U1. Ожидание: 403 `error.dashboard.forbidden`. 3) DELETE несуществующего id. Ожидание: 404.

## A3. Доступ и «disabled с ворнингом»

### TC-A3-02 Библиотека для CLIENT
- Шаги: как CLIENT. Ожидание: `BANK_FLOW`, `BANK_PENDING`, `PAYROLL_TOTAL` недоступны.

### TC-A3-03 Добавление недоступного виджета
- Шаги: WORKER `POST` `PAYROLL_TOTAL`. Ожидание: 403 `error.dashboard.widget.disabled`.

### TC-A3-04 «Любая операция на ресурсе» = доступ
- Предусловия: тестовая роль `DASH_{RUN_ID}` без прав; пользователь с этой ролью; admin-API матрицы.
- Шаги:
  1. Библиотека: `PAYMENTS_RECEIVED.available=false`.
  2. Выдать роли только `PAYMENTS/READ`. Библиотека: `available=true`.
  3. Заменить на только `PAYMENTS/DELETE`. Ожидание: `available=true` (любая операция).
  4. Снять все операции. Ожидание: `available=false`.

### TC-A3-05 Потеря доступа у размещённого виджета
- Шаги: 1) Роль с `PAYMENTS/READ`, добавить `PAYMENTS_RECEIVED`. 2) Снять право. 3) `GET /api/dashboard`: `state=NO_ACCESS`. 4) `GET .../data`: 403 `widget.disabled` (`reason=NO_ACCESS`). 5) Вернуть право: `state=AVAILABLE`, данные 200. Тот же item без повторного добавления.

### TC-A3-06 Деактивированный виджет
- Шаги: ADMIN `POST /api/dashboard-widgets/{id}/deactivate`. У пользователя: library не содержит виджет; layout `state=INACTIVE`; data 403 (`reason=INACTIVE`). `activate` возвращает AVAILABLE.

## A4. Выборка данных и безопасность

### TC-A4-01 Фильтр по проектам токена
- Предусловия: отчёты о работе в проектах A и B; MANAGER участник только A.
- Шаги: `GET .../data` виджета `WORK_REPORTS_PENDING` у MANAGER. Ожидание: все строки только проекта A.

### TC-A4-02 ADMIN видит все проекты
- Шаги: тот же виджет у ADMIN. Ожидание: строки проектов A и B.

### TC-A4-03 WORKER видит только свои отчёты
- Шаги: `MY_WORK_REPORTS` и `WORK_REPORTS_BY_STATUS` у WORKER. Ожидание: все строки `worker.id` = WORKER (owner restriction); счётчики не включают чужие отчёты.

### TC-A4-04 Диапазон дат
- Шаги: 1) `dateFrom/dateTo` текущий месяц: ожидание — только отчёты месяца. 2) `dateFrom > dateTo`: 400 `error.dashboard.date.invalid`. 3) Диапазон > 5 лет: 400. 4) Отсутствие параметров: 400. 5) Виджет без `dateField` игнорирует диапазон.

### TC-A4-05 Нельзя расширить доступ параметрами
- Шаги: `GET .../data?projectId=B&userId=1` как MANAGER. Ожидание: параметры игнорируются, данные не расширяются.

### TC-A4-06 Агрегации
- Шаги: подготовить 3 платежа CONFIRMED (100, 200, 300) и 1 PENDING (50) в диапазоне. `PAYMENTS_RECEIVED`: значение `600.00`, `previous` присутствует.

### TC-A4-07 Усечение
- Шаги: подготовить >200 строк, запросить TABLE с `limit=200`. Ожидание: `rows.length<=200`, `truncated=true`.

### TC-A4-08 Каталог датасетов покрывает ресурсы
- Шаги: 1) ADMIN `GET /api/dashboard-widgets/datasets`. Ожидание: 38 датасетов; у каждого заполнены `requiredResources`, поля с флагами возможностей. 2) `GET /api/resources`. Ожидание: каждый ресурс, кроме справочников (MEASUREMENT_UNITS, CURRENCIES, VAT_RATES, ROOM_TYPES, WORKER_TYPES, WORK_CATEGORIES, DELIVERY_CATEGORIES, DELIVERY_STATUSES, UNPLANNED_EXPENSE_CATEGORIES, MATERIAL_CATEGORIES, MATERIAL_TYPES, MATERIALS, MATERIAL_PRODUCERS, MATERIAL_SELLERS, CONSTRUCTION_MATERIAL_TYPES, OFFER_PACKAGES, PACKAGE_ASSORTMENT), RESOURCES, OPERATIONS и EXPENSE_UPLOAD, присутствует в `requiredResources` хотя бы одного датасета.

### TC-A4-09 Чувствительные поля недоступны
- Шаги: 1) По каталогу убедиться, что нет полей `iban`, `accountNumber`, `email`, `phone`, `nip`, `snapshotBefore/After`, `body`, `deepLink`, `originalText`, `documentUri`, `storageUri`. 2) `POST /api/dashboard-widgets/validate` с конфигом, выбирающим `USERS.email`. Ожидание: 400 `error.dashboard.config.invalid`.

### TC-A4-10 Датасеты по группам: скоупинг
- Шаги (для MANAGER, участника только проекта A; данные созданы в A и B): запросить через превью/виджеты по одному агрегату `COUNT(id)` для каждого проектного датасета (`ROOMS`, `ESTIMATES`, `ESTIMATE_LINES`, `OFFERS`, `AMENDMENTS`, `AMENDMENT_LINES`, `SIGNABLE_DOCUMENTS`, `PURCHASE_LINES`, `PAYMENT_SCHEDULES`, `PAYMENT_TRANCHES`, `CLIENT_MESSAGES`, `SCHEDULE_BARS`). Ожидание: счёт равен числу записей проекта A; для ADMIN — A+B.

### TC-A4-11 NOTIFICATIONS — всегда свои
- Шаги: ADMIN считает `COUNT(id)` по датасету `NOTIFICATIONS`. Ожидание: совпадает с `GET /api/notifications` ADMIN (чужие уведомления не учитываются).

## A5. Админка: CRUD, валидация, превью

### TC-A5-01 Доступ к админ-эндпоинтам
- Шаги: MANAGER вызывает `GET /api/dashboard-widgets`. Ожидание: 403. ADMIN: 200.

### TC-A5-03 Невалидные конфиги
- Шаги (каждый — 400 `error.dashboard.config.invalid` со списком нарушений): неизвестный dataset; неизвестное поле; SUM по текстовому полю; PIE без measure; KPI с dimension; пустые RU/PL строки; `limit=0` и `limit=500`; ссылка на `https://evil.example`; `javascript:`; маршрут не из whitelist; `SINGLE_PROJECT` на датасете `PAYROLL`; config >64 KB; `schemaVersion=99`.

### TC-A5-04 Превью
- Шаги: `POST /preview` с валидным config и диапазоном. Ожидание: 200, `WidgetResult`; в БД ничего не создано (`GET` списка не изменился). Превью невалидного config: 400.

### TC-A5-06 Удаление

### TC-A5-07 Обновление config
- Шаги: PUT нового заголовка. Ожидание: размещённые виджеты получают новый заголовок без перерисовки макета; `code` изменить нельзя (игнорируется/400).

### TC-A5-08 Аудит
- Шаги: create/update/deactivate/delete → записи в `/api/audit`.

# Часть B. UI (браузерный движок)

Все UI-тесты — под пользователями из Setup. Язык интерфейса переключается PL/RU.

## B1. Страница Panel

### TC-B1-01 Отображение сетки
1. Логин MANAGER, открыть `/`. Ожидание: сетка виджетов, 4 колонки на ширине 1440.
2. Уменьшить окно до 900 → 3 колонки; до 400 → 1 колонка. Порядок плиток сохраняется (по cellIndex).
3. Многоклеточные плитки занимают заданные колонки/строки на десктопе; на мобильном — ширина в 1 колонку.

### TC-B1-02 Состояния плитки
1. Эмуляция медленного ответа: у плитки спиннер/скелетон.
2. Эмуляция 500 на одном виджете: плитка показывает ошибку и «Повторить»; остальные плитки работают.
3. Пустые данные: «Нет данных».

### TC-B1-03 Пустое состояние и «+»
1. Пользователь без виджетов: пустое состояние и плитка «+» в первой ячейке.
2. При частично заполненной сетке «+» находится в первой свободной ячейке.

## B2. Глобальный фильтр дат

### TC-B2-01 Значение по умолчанию
1. Новая сессия браузера: «От»/«До» = первое и последнее число текущего месяца.

### TC-B2-02 Быстрый выбор
1. Выбрать «Прошлый» + «Месяц» → предыдущий календарный месяц; «Позапрошлый» + «Неделя» → неделя (пн-вс), две недели назад; «Текущий» + «Год»; «Текущий» + «День» (from = to = сегодня).
2. После каждого выбора виджеты выполняют refetch с новыми `dateFrom/dateTo` (проверка по сетевым запросам).

### TC-B2-03 Запоминание в сессии
1. Установить диапазон, перезагрузить страницу: диапазон сохранён.
2. Открыть новую сессию (новый контекст браузера): текущий месяц.

### TC-B2-04 Валидация
1. Ввести «От» > «До»: сообщение об ошибке, запрос не уходит.
2. Диапазон > 5 лет: сообщение.

### TC-B2-05 Виджеты без привязки к дате
1. У плитки без `dateField` отображается пометка «Не зависит от фильтра дат».

## B3. Добавление и удаление

### TC-B3-01 Добавление из библиотеки
1. Нажать «+», открыть выбор; поиск по названию фильтрует список.
2. Выбрать доступный виджет: он появляется в ячейке «+»; список обновился.

### TC-B3-02 Недоступные виджеты в выборе
1. Как WORKER открыть выбор: виджеты зарплат/банка отображены disabled с иконкой предупреждения; tooltip содержит названия недостающих ресурсов; клик не добавляет.

### TC-B3-03 Проектный виджет
1. Выбрать `PROJECT_CARD`: показывается выбор проекта (по умолчанию только активные, поиск).
2. Выбрать проект A, затем снова добавить `PROJECT_CARD` для проекта B: две плитки с названиями проектов. Проект A повторно: ошибка/отключён в списке.

### TC-B3-04 Удаление с предупреждением
1. Нажать «Удалить» на плитке: открывается диалог с названием виджета и предупреждением.
2. «Отмена» — виджет остаётся. «Удалить» — плитка исчезает, «+» появляется на её месте (если это первая свободная ячейка).

### TC-B3-05 Нет места
1. Заполнить сетку; открыть выбор: сообщение «Нет свободного места», добавление недоступно.

### TC-B3-06 Disabled-плитка после смены матрицы
1. ADMIN снимает у роли право на ресурс размещённого виджета.
2. Пользователь обновляет страницу: плитка серая с предупреждением и причиной; данные не запрашиваются; кнопка «Удалить» работает.
3. Право возвращено: плитка снова рабочая.

## B4. Кликабельность

### TC-B4-01 Карточка проекта
1. Клик по названию проекта открывает `/projects/{id}`. Клик по чипу «Смета» / «Гант» / «Платежи» — соответствующая вкладка. Переход без полной перезагрузки.
2. Для пользователя без права на целевой маршрут элемент отображается не ссылкой.

### TC-B4-02 Таблица и диаграмма
1. Клик по строке таблицы `WORK_REPORTS_PENDING` ведёт к отчётам проекта.
2. Клик по сегменту диаграммы с настроенной ссылкой ведёт на целевой маршрут; без ссылки — курсор не меняется.
3. Навигация клавиатурой: Tab фокусирует ссылки, Enter активирует.

## B5. Админка: библиотека виджетов

### TC-B5-01 Навигация и права
1. ADMIN: раздел «Система» содержит «Виджеты панели»; MANAGER — пункта нет, прямой переход на `/dashboard-widgets` ведёт на экран «нет доступа».

### TC-B5-02 Список
1. Колонки: код, название, визуализация, датасет, размер, проектный, активен, роли. Поиск и фильтр «активные».

### TC-B5-03 Ручное создание с превью
1. «Создать»: заполнить код `TC_{RUN_ID}_UI`, имена RU/PL, размер 2x2.
2. Выбрать датасет `WORK_REPORTS`, визуализация BAR, группировка `status`, мера COUNT.
3. Превью рендерится (с debounce) и подписано «от имени администратора».
4. Сделать конфиг невалидным (убрать меру): инлайн-ошибки, сохранение заблокировано.
5. Исправить, сохранить: виджет появляется в списке; в выборе пользователя виджет доступен.

### TC-B5-04 Требуемые ресурсы и роли
1. В форме отображаются требуемые ресурсы датасета и список ролей, которым виджет виден.

### TC-B5-05 Деактивация/удаление
1. Деактивировать виджет с размещениями: у пользователя в колокольчике появляется уведомление, клик ведёт на `/`; плитка помечена как отключённая.
2. Удалить виджет с размещениями: сообщение «используется»; после удаления размещений — удаляется.

### TC-B5-06 ИИ-ассистент
1. Открыть панель ИИ, ввести описание, нажать «Создать»: индикатор, затем черновик заполняет форму, показано пояснение/предупреждения, ничего не сохранено до нажатия «Сохранить».
2. При сбое: сообщение об ошибке и уведомление в колокольчике с переходом на список виджетов.

## B5a. Оформление

### TC-B5a-01 Палитра по теме
1. В `/settings/appearance` выбрать другой акцентный цвет/тему. Ожидание: цвета диаграмм на Panel меняются без перезагрузки.

### TC-B5a-02 Своя палитра
1. Открыть «Настроить оформление», задать 3 цвета, сохранить: диаграммы используют их по порядку.
2. Ввести неверный цвет: сообщение об ошибке, сохранение заблокировано.
3. Ввести светлый цвет на светлом фоне: цвет скорректирован, показано предупреждение о контрасте.
4. «Сбросить»: возврат к палитре темы. Перезагрузка страницы сохраняет выбор.

### TC-B5a-03 Стиль виджета
1. В меню плитки выбрать стиль «Компактный» для таблицы: плитка перерисовывается; другие виджеты и другие пользователи не затронуты.
2. Для каждого типа визуализации в меню не менее трёх стилей; названия переведены PL/RU.
3. Выбрать «По умолчанию»: возврат к стилю, заданному админом.

### TC-B5a-04 Админ: стиль по умолчанию
1. В конструкторе выбрать стиль по умолчанию и цвета, «Показать все стили» отображает превью каждого стиля; сохранить. Пользователь без своего выбора видит заданный стиль.

## B6. Локализация и доступность

### TC-B6-01 Переключение языка
1. PL и RU: все подписи Panel и админки переведены (нет сырых ключей `dashboard.*`); названия виджетов и подписи конфигов берутся из соответствующего языка.

### TC-B6-02 Клавиатура и размеры касания
1. Все действия (фильтр дат, «+», удаление, ссылки) доступны с клавиатуры, видимый фокус. На мобильном размер элементов касания ≥ 44px.

# Регрессия

### TC-R-01 Права на панели не расширяются
Повторить TC-A3-01..05 и TC-A4-01..03 после любого изменения матрицы прав или датасетов.

### TC-R-02 Сквозной путь нового пользователя
Создать пользователя → логин → дефолтный дашборд (A1-01) → смена диапазона дат (B2-02) → добавление проектного виджета (B3-03) → клик по чипу (B4-01) → удаление (B3-04).

### TC-R-03 Не сломаны существующие экраны
Колокольчик уведомлений (список, прочитано/не прочитано, удаление), меню «Система», список проектов открываются без ошибок консоли.

### TC-R-04 Миграции
Повторный запуск Liquibase на уже заполненной БД: ошибок и дублей нет (сиды идемпотентны, бэкфилл не дублирует размещения).
