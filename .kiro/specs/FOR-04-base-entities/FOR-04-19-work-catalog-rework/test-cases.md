# Тест-кейсы: FOR-04-19 — Переработка каталога работ

Тип спеки: **UI + API**. Кейсы исполняются браузерным движком (headless-браузер) и HTTP-клиентом
против Docker-стека (`docker compose up`: frontend `http://localhost:3000`, backend
`http://localhost:8080`, профиль `docker`). Перед прогоном убедиться, что Liquibase применён
(индекс `ix_wmc_work_item_branch` на `work_material_consumptions (work_item_id, branch)`).
Результат прогона — MD-репорт с таблицами (шаблон в конце файла); скриншоты не требуются.

Покрываемые требования: 1.x, 2.1, 2.3, 3.1, 4.1, 5.3, 6.1, 10.5 (и сопутствующие 2.x–6.x).

## Особенности реализации (учитывать при прогоне)

- **Колонки «Basis» («Podstawa») в инлайн-таблице норм НЕТ.** Бэкенд не отдаёт `consumptionBasis`
  в DTO нормы, поэтому таблица содержит только: Typ materiału · Jednostka · Norma · Straty % ·
  Cena (zakres) · действия. Базис при создании уходит как `PER_UNIT` по умолчанию и в UI не
  проверяется.
- **Диапазон `Straty %` (wastePct): 0–999.99** (NUMERIC(5,2)). Значение `150` — валидно,
  ошибка начинается с `1000`.
- **Счётчики `constructionConsumptionCount` / `finishingConsumptionCount` приходят только в списке**
  (`GET /api/work-items`), на одиночном `GET /api/work-items/{id}` их нет — страница редактирования
  считает группы по строкам таблицы норм. Проверять счётчики только через список.
- Колонки счётчиков не сортируются; фильтр — трёхпозиционный: Wszystkie / Z normami (`>0`) /
  Bez norm (`==0`).
- `normQty` ∈ [0; 99999999.9999]; для новой строки по умолчанию `sourceType=manual`,
  `sourceDoc` = «Wprowadzono w katalogu prac» / «Введено в каталоге работ», `sourceRef` = дата.

Роли: ADMIN (полные права), MANAGER (CRU без DELETE), FOREMAN (только READ каталога).
Вьюпорты: Desktop 1280×800, Mobile 390×844.

## Повторяемость

Стратегия: **генератор данных + teardown**.

- `run-id` = `YYYYMMDDHHmmss`. Все тестовые работы называются `RW-{run-id}-{n}` (nameRU и namePL),
  нормы создаются только на этих работах. Тестовые пользователи — `rw+{role}-{run-id}@example.com`.
- **Setup (API, ADMIN-токен, `POST /api/auth/login`):** создать 3 работы в одной категории:
  - `RW-{run-id}-1` — без норм;
  - `RW-{run-id}-2` — одна норма `construction`;
  - `RW-{run-id}-3` — по две нормы `construction` и `finishing`.
  Нормы создаются `POST /api/work-material-consumptions` (типы/единицы брать первыми из
  `/api/construction-material-types`, `/api/material-types`, `/api/measurement-units`).
- **Teardown (всегда, даже при падении):** `DELETE /api/work-material-consumptions/{id}` для всех норм
  работ `RW-{run-id}-*`, затем `DELETE /api/work-prices/{id}` (если создавалась цена), затем
  `DELETE /api/work-items/{id}`; деактивировать/удалить тестовых пользователей. Работы, созданные
  через UI в TC-B1, удаляются так же.
- Проверка чистоты: `GET /api/work-items?query=nameRU~ct~RW-{run-id}` после teardown → пусто.

### TC-D6. Живая валидация итоговой формулы (Req 6.1–6.4)
Проверять текст статуса под полем (`role="status"`) и состояние Save.

| Формула (ввод) | Ожидание |
|----------------|----------|
| `floorArea * 2 + perimeter` | «Formuła jest poprawna» (зелёный), Save доступен |
| `-floorArea + (2 * 3)` | Корректна (унарный минус в начале и после `(`) |
| `2.5 * wallArea` | Корректна (десятичная точка) |
| *(пусто)* в формуле работы | Не ошибка; Save очищает формулу |
| *(пусто)* в строке пакета | «Formuła jest pusta» / переопределения нет, без блокировки сохранения пустой строки по правилам редактора |
| `2 floorArea`, `floorArea perimeter` | «Brak operatora między wartościami» |
| `2 ++ 3`, `2 * / 3`, `2 - -3` | «Dwa operatory pod rząd» |
| `* 3`, `(* 3)` | «Formuła nie może zaczynać się od operatora» |
| `2 +`, `(2 +)` | «Formuła nie może kończyć się operatorem» |
| `(2 + 3` / `2 + 3)` | «Niezgodne nawiasy» |
| `()` | «Puste nawiasy» |
| `2 / 0` | «Dzielenie przez zero» |
| `foo + 2` | «Nieznany element: foo», слово подсвечено |
| `2 $ 3` | «Niedozwolony znak: $» |
| `IFS(1,2)` / `X28 + 1` | Ошибка неизвестного элемента (вне нового подмножества) |

При любой ошибке: Save секции отключён, поле `aria-invalid="true"`, для строки пакета коммит
заблокирован. Валидация срабатывает ≤ ~150 мс после ввода. Сообщения переводятся при смене языка.
