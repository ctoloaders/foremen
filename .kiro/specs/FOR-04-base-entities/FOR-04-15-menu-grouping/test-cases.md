# Тест-кейсы: FOR-04-15 — Группировка главного меню («Каталог» / «Справочники»)

## Назначение и характер спеки

Это **чисто UI-спека** (фронтенд, навигация). Бэкенда, БД, ABAC-ресурсов и новых
страниц/маршрутов она не добавляет — только две группы в `NAV_CONFIG`, два
i18n-ключа заголовков секций (`nav.sections.catalog`, `nav.sections.dictionaries`)
и сворачиваемый заголовок группы «Справочники».

Тест-кейсы — **браузерные сценарии**, исполняемые браузерным движком (headless /
browser automation) против работающего фронтенда `http://localhost:3000`.
Результат прогона — **MD-репорты с таблицами (без скриншотов)**.

**Стратегия повторяемости:** сценарии — **только чтение навигации** (переходы,
раскрытие/сворачивание меню, проверка видимости пунктов). Никаких сущностей не
создаётся и не изменяется, поэтому teardown и генератор данных **не требуются**.
Единственное требование к окружению — наличие пользователей разных ролей (ADMIN и
как минимум одна ограниченная роль, например CLIENT и READ-роль вроде WORKER) для
проверки пермишн-фильтрации. Каждый прогон — независимые сессии логина под нужной
ролью; выход из сессии в конце.

## Запуск окружения

`docker compose up` в корне поднимает `postgres`, `liquibase`, `backend` (:8080),
`frontend` (:3000). Базовый URL UI — `http://localhost:3000`. Первый ADMIN
поднимается через `FOREMEN_ADMIN_CREATE=true` + `FOREMEN_ADMIN_EMAIL` +
`FOREMEN_ADMIN_PASSWORD`. Для ролевых кейсов нужны учётки с ролями CLIENT и
READ-ролью (WORKER/FINANCIER) — если их нет, ADMIN создаёт их заранее через
страницу Users (это подготовка окружения, а не часть данного набора).

## Общий Setup

### TC-SETUP-01 — Вход под ADMIN
Открыть `http://localhost:3000`, ввести email/пароль ADMIN, дождаться редиректа в
панель. Ожидание: боковое меню (Sidebar) отрисовано.

---

## Фича 1. Группа «Каталог»

Покрывает R1, R5, R6.

### TC-01 — Секция «Каталог» присутствует и локализована (ADMIN)
Под ADMIN раскрыть боковое меню. Ожидание: между первой (безымянной) группой и
группой «Склад»/«Magazyn» присутствует заголовок «Каталог» (RU) / «Katalog» (PL),
без сырого ключа `nav.sections.catalog`.

### TC-02 — Пункты «Каталог работ» и «Цены работ» и их порядок
В группе «Каталог» присутствуют, в порядке: «Каталог работ» (`nav.workCatalog`),
«Цены работ» (`nav.workPrices`). Ожидание: оба видны, с иконками.

### TC-03 — Переходы по пунктам «Каталог»
Клик по «Каталог работ» → URL `/catalog/works`, открылась страница каталога
(заголовок `workCatalog.pageTitle`). Клик по «Цены работ» → URL `/catalog/prices`,
открылась страница цен. Ожидание: маршруты совпадают, «мёртвых» ссылок нет.

### TC-04 — «Каталог» не в нижней панели (BottomNav)
На мобильной ширине (bottom-bar активен) проверить нижнюю панель. Ожидание:
пункты «Каталог работ»/«Цены работ» в bottom-bar отсутствуют (у них
`bottomNav: false`); состав нижней панели не изменился относительно baseline.

---

## Фича 2. Группа «Справочники»

Покрывает R2, R3, R5, R6.

### TC-05 — Секция «Справочники» присутствует и локализована (ADMIN)
Под ADMIN между группой «Склад» и группой «Система»/«System» присутствует
заголовок «Справочники» (RU) / «Słowniki» (PL), без сырого ключа
`nav.sections.dictionaries`.

### TC-06 — Все девять пунктов и их порядок (ADMIN)
В раскрытой группе «Справочники» присутствуют, в порядке: Единицы измерения,
Валюты, Ставки НДС, Типы помещений, Категории работ, Категории доставок, Статусы
доставок, Категории материалов, Пакеты предложений (`nav.measurementUnits`,
`nav.currencies`, `nav.vatRates`, `nav.roomTypes`, `nav.workCategories`,
`nav.deliveryCategories`, `nav.deliveryStatuses`, `nav.materialCategories`,
`nav.offerPackages`).

### TC-07 — Переходы по пунктам «Справочники»
Поочерёдно кликнуть каждый пункт и проверить URL: `/measurement-units`,
`/currencies`, `/vat-rates`, `/room-types`, `/work-categories`,
`/delivery-categories`, `/delivery-statuses`, `/material-categories`,
`/offer-packages`. Ожидание: каждый маршрут открывает свою страницу (её
`pageTitle`), «мёртвых» ссылок нет.

### TC-08 — Сворачивание/разворачивание группы «Справочники»
Кликнуть по заголовку «Справочники». Ожидание: список пунктов скрывается,
`aria-expanded` заголовка становится `false`, сам заголовок остаётся видимым.
Повторный клик — пункты снова видны, `aria-expanded=true`.

### TC-09 — Клавиатурная доступность тоггла
Сфокусировать заголовок «Справочники» с клавиатуры (Tab), нажать Enter, затем
Space. Ожидание: каждое нажатие переключает состояние; у элемента есть доступное
имя, равное локализованному заголовку.

### TC-10 — Только «Справочники» сворачиваемые
Проверить, что заголовки других групп («Склад», «Система», «Настройки») —
не кнопки-тогглы (нет `aria-expanded`, клик по ним ничего не сворачивает).

## Фича 3. Пермишн-фильтрация групп

Покрывает R1.5/1.6, R2.5/2.6, R4.4, R6.2.

### TC-11 — READ-роль видит только доступные пункты
Войти под READ-ролью (например WORKER: READ на большинство справочников и
каталога, но без некоторых). Ожидание: в группах «Каталог»/«Справочники» видны
только пункты с READ на соответствующий ресурс; недоступные пункты скрыты;
заголовок группы виден, если есть хотя бы один доступный пункт.

### TC-12 — CLIENT не видит «Каталог» и «Справочники»
Войти под CLIENT (нет READ на ресурсы каталога и справочников). Ожидание:
заголовки «Каталог» и «Справочники» и все их пункты отсутствуют (section
suppression).

### TC-13 — Прямой заход без прав → /403
Под CLIENT перейти напрямую по URL `/currencies` (или `/catalog/works`).
Ожидание: интерим-гард FOR-03-07 блокирует → редирект на `/403`. Поведение
неизменно относительно спек-источников страниц.

### TC-14 — Projects / Rooms привязаны к реальным ресурсам
Под ADMIN и под ролью без `ROOMS`/`PROJECTS` READ проверить первую безымянную
группу. Ожидание: пункты «Проекты» (`/projects`, `PROJECTS/READ`) и «Помещения»
(`/rooms`, `ROOMS/READ`) на месте у ADMIN; скрыты у роли без соответствующего
READ; из первой группы не перемещены.
