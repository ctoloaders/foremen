# Тест-кейсы: FOR-04-12b — Package-based Work Prices (пивот-каталог цен по пакетам)

## Назначение и характер спеки

Спека имеет **и API-поверхность, и браузерный экран**. Цены работ раздаются через REST
`/api/work-prices` **и** через админ-страницу пивот-каталога (`/catalog/prices`). Ключевое отличие
от FOR-04-12: `WorkPrice` теперь **агрегатор по позиции** (уникальная связь с `WorkItem`, БЕЗ
`netPrice`/`currency`/`validFrom`/`validTo`), владеющий коллекцией `packagePrices` из новой
join-сущности `WorkPackagePrice` (`work_price_id` + `offer_package_id` + `currency_id` + `net_price`,
уникум по `(work_price_id, offer_package_id)`). Цена конкретного пакета вычисляется резолвером с
max-fallback. Фильтрация/сортировка по цене пакета выражается через **Pivot_Key**
`prices.{packageId}.{field}` и резолвится сервером единым **Custom_Predicate_Flow** (один
`CustomQueryResolver` владеет и `toFilter`, и `toSort`, поэтому фильтр и сортировка не расходятся).

Набор тест-кейсов включает **оба типа**:

- **Часть A. API-тесты** — против работающего в Docker приложения. Каждый шаг — HTTP-запрос к
  `/api/work-prices` (и смежным эндпоинтам). Результат прогона — MD-репорт с таблицами.
- **Часть B. Браузерные (UI) сценарии** — против фронтенда `http://localhost:3000`, browser
  automation / headless, под ролью ADMIN. Результат прогона — MD-репорт с таблицами.

Результат прогона для обеих частей — **MD-репорты с таблицами** (шаг → запрос/действие → ожидание →
факт → статус). **Скриншоты не требуются.**

Покрываемые требования: **R1** (агрегатор + join-сущность, три FK, каскады `ON DELETE CASCADE` на
`work_price_id`/`offer_package_id`/`work_prices.work_item_id`, RESTRICT на `currency_id`, уникум
`(work_price_id, offer_package_id)`), **R2** (миграция fan-out), **R3** (резолвер эффективной цены с
max-fallback), **R4** (пивот-фильтр/сортировка через Custom_Predicate_Flow, ошибки unknown-id /
unknown-field, идентичные для фильтра и сортировки, `/metadata` пивот-дескрипторы), **R5** (пивот-
колонки `Cena {label}`, placeholder для непрайсованной строки, апсерт `packagePrices`), **R6** (сид
per-package из Excel), **R7** (ABAC `WORK_PRICES` без изменений), **R8** (бэкенд-тесты), **R9**
(фронтенд-тесты), **R10** (i18n PL/RU).

## Запуск окружения

1. В корне репозитория: `docker compose up` — поднимает `postgres` (:5432), `liquibase` (миграции,
   включая `044`/`045`), `backend` (:8080, профиль `docker`), `frontend` (:3000).
2. Базовый URL для API-тестов: `http://localhost:8080`; auth — под `/api/auth`.
3. Первый ADMIN — через `FOREMEN_ADMIN_CREATE=true`, `FOREMEN_ADMIN_EMAIL`, `FOREMEN_ADMIN_PASSWORD`
   (в `docker-compose.yml`: `cto+1@loaders.dev` / `alejano123`).
4. Дождаться готовности `backend` и завершения миграций (`044` fan-out + `045` per-package сид) перед
   прогоном.
5. **Предзависимости по данным:** для апсерта `WorkPrice` нужны существующие `WorkItem` (засижены из
   CSV), `OfferPackage` (`budget`/START, `norm`/COMFORT, `lux`/PRESTIGE — FOR-04-10) и `Currency`
   (PLN — FOR-04-03). Их id получить через `GET /api/work-items?size=1000`,
   `GET /api/offer-packages?size=1000`, `GET /api/currencies?size=1000`.

## Стратегия повторяемости (обязательно)

**Комбинированная — генератор + teardown** (единая для частей A и B):

1. **Run-id генератор.** На прогон формируется `run-id` = timestamp/uuid (например
   `20260101-120000-ab12`). Чтобы не конфликтовать с уникумом `uk_work_prices_work_item` (максимум
   один `WorkPrice` на позицию), кейсы, создающие агрегаторы, **создают новую тестовую позицию
   каталога** `WorkItem` с `name_pl` вида `TC WP {run-id}` через `POST /api/work-items` и используют
   её `id`. Реальные id фиксируются в переменные прогона: `WI_TC` (тестовая позиция), `PID_BUDGET`,
   `PID_NORM`, `PID_LUX` (id пакетов), `CUR_PLN` (id PLN), `WPID` (id созданного агрегатора).
2. **Teardown.** По завершении набора:
   - удалить созданный агрегатор `DELETE /api/work-prices/{WPID}` (каскадом уходят его
     `WorkPackagePrice`);
   - удалить тестовую позицию `DELETE /api/work-items/{WI_TC}` (каскадом уходит и агрегатор, если не
     удалён на предыдущем шаге — проверка R1.9);
   - разлогинить/погасить токены.
3. **Seed-данные (позиции/цены из CSV, пакеты, валюты) и системные ресурсы/роли НЕ изменяются** —
   только читаются. Кейсы каскадного удаления пакета/валюты работают на **специально созданных для
   прогона** пакете и валюте (не на сид-строках), чтобы не разрушить общий каталог.

Каждая фича ниже явно указывает свою стратегию повторяемости.

### Замечание про non-ADMIN роли (ABAC)

Бутстрапится только ADMIN. Кейсы non-ADMIN ролей документируются ожидаемыми результатами и
покрываются seed-интеграционным тестом (`WorkPricesResourceSeedIntegrationTest`). Матрица
`WORK_PRICES` **не изменяется** этой спекой: **ADMIN — CRUD; MANAGER — CREATE/READ/UPDATE (без
DELETE); FOREMAN/WORKER/FINANCIER — READ; CLIENT — без гранта**.
