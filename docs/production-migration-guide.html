Шаг 1: Создать Telegram Bot для клиента

1Делает клиент. Каждый клиент — отдельный бот.

Как создать:

  1. Открыть Telegram → найти @BotFather
  2. Отправить /newbot
  3. Ввести имя бота (видно пользователям): например Foremen Receipts
  4. Ввести username бота (уникальный): например foremen_receipts_bot
  5. BotFather вернёт токен — скопировать

Дополнительные настройки (опционально):

  1. Отправить /setdescription → выбрать бота → написать описание
  2. Отправить /setuserpic → загрузить логотип клиента
  3. Отправить /setcommands → вставить: 
    start - Начать работу / выбрать проект
myid - Показать мой Telegram ID
cancel - Отменить текущее действие
Результат: токен вида 1234567890:ABCdef... — записать в TELEGRAM_BOT_TOKEN

Шаг 2: Google Cloud + Shared Drive

2.1 Google Cloud Project + Service Account (делает клиент)

  1. Перейти: console.cloud.google.com
  2. Создать новый проект (или использовать существующий)
  3. Привязать Billing Account (обязательно для Cloud Functions)
  4. Включить APIs: Google Sheets API, Google Drive API
  5. IAM & Admin → Service Accounts → Create → имя: foremen-bot → роль: Editor
  6. Создать ключ: JSON → скачать файл → передать нам
JSON-ключ содержит private key. Передавать только через защищённый канал.

2.2 Shared Drive (делает клиент)

  1. Google Drive → Shared drives → "+ New" → назвать: Foremen — [Компания]
  2. Добавить Service Account как участника (email из JSON-ключа) → роль: Content Manager
Результат: клиент даёт нам JSON-ключ SA. Всё остальное (папки, реестры) создаёт наш setup-скрипт.

2.3 Всё остальное — наш скрипт (делаем мы)

Имея SA JSON-ключ, setup-скрипт автоматически:

  • Создаёт папку "Проекты" в Shared Drive
  • Создаёт все спредшиты (реестр работников, реестр проектов)
  • Настраивает заголовки и форматирование
  • Добавляет первого админ-пользователя

Шаг 3: Деплой сервера (делаем мы)

Вариант A: Google Cloud Functions (рекомендуется)

Требования: billing привязан, APIs включены, gcloud CLI установлен.

# Авторизация
gcloud auth login
gcloud config set project YOUR_PROJECT_ID

# Деплой (из папки telegram-bot/)
bash deploy.sh

После деплоя получишь два URL:

  • Telegram webhook URL: https://REGION-PROJECT.cloudfunctions.net/receipt-bot
  • Bitrix webhook URL: https://REGION-PROJECT.cloudfunctions.net/bitrix-webhook

Настроить Telegram webhook:

curl "https://api.telegram.org/bot<TOKEN>/setWebhook?url=<TELEGRAM_WEBHOOK_URL>&secret_token=<WEBHOOK_SECRET>"

Вариант B: VPS (если нет billing)

  1. Арендовать VPS (Hetzner, DigitalOcean, ~$5/мес)
  2. Установить Node.js 20 + bun
  3. Склонировать репо, bun install, создать .env
  4. Запустить через PM2: pm2 start "bun src/dev-webhook.ts" --name webhook
  5. Настроить nginx reverse proxy для HTTPS
  6. Для Telegram бота: запустить в webhook mode (не polling)

Шаг 4: Настройка Битрикс24 клиента

4.1 Входящий webhook (ПЕРВЫМ ДЕЛОМ) (делает клиент)

Это нужно сделать первым — чтобы мы могли автоматически определить коды полей.

  1. Разработчикам → Готовые сценарии → Другое → Входящий вебхук
  2. Права: ☑ CRM, ☑ Пользователи (user)
  3. Сохранить → скопировать URL
Результат: URL вида https://XXX.bitrix24.ru/rest/1/YYYYY/ — дать нам этот URL.

4.2 Поля в профиле сотрудника (создаём мы через API, или клиент вручную)

Наш setup-скрипт проверит наличие полей и создаст недостающие через API. Если API не позволяет — клиент создаёт вручную:

4.4 Setup-скрипт: парсим коды + генерируем конфиги (делаем мы)

Получив URL входящего webhook от клиента, запускаем setup-скрипт:

# Запуск:
bun scripts/setup-client.ts \
  --telegram-token="TOKEN" \
  --sa-key="./client-sa.json" \
  --bitrix-url="https://XXX.bitrix24.ru/rest/1/YYYYY/"

Скрипт автоматически:

  1. Проверяет наличие нужных полей в Битрикс, создаёт недостающие через API
  2. Парсит коды всех полей
  3. Создаёт Shared Drive + папки + реестры (Google)
  4. Генерирует готовый .env файл
  5. Генерирует готовое тело запроса для робота (JSON) — отправить клиенту для вставки
Клиенту отдаём: готовый JSON для робота + инструкцию "вставь это в робот".

4.5 Робот на сделке (мы даём готовый JSON — клиент вставляет)

Мы отправляем клиенту готовый JSON (сгенерирован на шаге 4.4). Клиент:

  1. CRM → Сделки → Роботы → на первой стадии добавить "Запрос по URL"
  2. URL: мы даём URL (Cloud Function bitrix-webhook)
  3. Метод: POST, тип: JSON
  4. Тело: вставить JSON который мы дали

Пример сгенерированного тела (коды полей подставлены автоматически):

  "secret": "СЕКРЕТ_КЛИЕНТА",

  "project_name": "{{Название}}",
  "deal_id": "{{ID}}",
  "bitrix_webhook_url": "https://XXX.bitrix24.ru/rest/1/YYYYY/",
  "google_drive_url": "{{UF_CRM_DRIVE_CODE}}",
  "google_sheets_url": "{{UF_CRM_SHEETS_CODE}}",

    {"worker_id": "{{UF_CRM_FOREMAN_CODE}}", "worker_name": "", "role_in_project": "foreman"},

Как получить коды полей клиента:

После того как клиент создал входящий webhook (шаг 4.3) — мы сами парсим коды:

# Получить все поля сделки (найти UF_CRM_* поля)
curl -s "https://XXX.bitrix24.ru/rest/1/YYYYY/crm.deal.fields" | python3 -c "
import json, sys
data = json.load(sys.stdin)
for k, v in data.get('result', {}).items():
    if k.startswith('UF_CRM'):
        print(f'{k} → {v.get(\"formLabel\", v.get(\"title\", \"?\"))}')"

# Получить все поля пользователя (найти UF_USR_* поля)
curl -s "https://XXX.bitrix24.ru/rest/1/YYYYY/user.fields" | python3 -c "
import json, sys
data = json.load(sys.stdin)
for k, v in data.get('result', {}).items():
    if k.startswith('UF_USR'):
        print(f'{k} → {v}')"

Результат будет вида:

UF_CRM_1785938336262 → Drive URL
UF_CRM_1785938353178 → Sheets URL
UF_CRM_1785938403 → Прораб
UF_CRM_1785938421 → Менеджер
UF_USR_1785937945029 → Telegram ID
UF_USR_1785938002037 → Роль для бота

Подставляешь эти коды в .env:

BITRIX_DRIVE_URL_FIELD=UF_CRM_...
BITRIX_SHEETS_URL_FIELD=UF_CRM_...
BITRIX_TELEGRAM_ID_FIELD=UF_USR_...
BITRIX_ROLE_FIELD=UF_USR_...
Клиенту не нужно знать про коды полей. Он создаёт поля в интерфейсе + входящий webhook. Мы сами получаем коды одной командой.
"action": "upsert_project", "project_name": "Тест продакшен", "deal_id": "1", "bitrix_webhook_url": "<BITRIX_INCOMING_WEBHOOK_URL>", "workers": [{"worker_id": "1", "worker_name": "", "role_in_project": "pm"}] }'

Ожидаемый ответ: {"status":"ok","message":"project created with new resources","google_drive_url":"...","google_sheets_url":"..."}

6.2 Проверить Telegram бот

  1. Открыть бота клиента в Telegram
  2. Отправить /myid → должен вернуть ID
  3. Убедиться что работник есть в реестре (workers sheet)
  4. Отправить /start → должен показать проекты
  5. Пройти полный флоу: фото → сумма → описание → магазин
  6. Проверить что фото загрузилось в Shared Drive и строка в смете

6.3 Проверить Битрикс24 робота

  1. Создать новую сделку в CRM
  2. Назначить прораба и менеджера
  3. Перевести на стадию где стоит робот (или он на первой)
  4. Проверить что поля Drive URL и Sheets URL заполнились автоматически
  5. Проверить Google Sheets реестры — проект и работники появились
  6. В Telegram боте /start — новый проект должен быть виден
